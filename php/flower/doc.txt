花データ（個別JSON）

id と name を基準に同一の花を対応させる。ファイル名のみで判定しない。
001 ジニア / 002 スイレン / 003 桜 / 004 ひまわり / 005 サルスベリ
006 ムクゲ / 007 コキア / 008 ハス / 009 ルリマツリ / 010 アジサイ
資料の「ヒマワリ」は既存の id=4 / name=ひまわり と同じ花として扱う。

出典：卒業制作データ一覧 のコピー.xlsx「花データ」A18:L27。
能力値・強化ID・スキルID・属性・日付・花言葉を資料から転記。
起源・咲いている場所・特徴は flower.json の同一 id/name を継承。
description は既存の概要、ない場合は features を使用。未記載項目は空文字。

id: 花ID（重複不可）
eng: 既存画像に対応する英字識別名
name: 表示名
※スキルIDや属性IDは花IDとは別の値。
enhance_id: 資料C列の強化ID（1〜6）
skill_id: 資料E列のスキルID。スキル実装側との照合は読み込み切り替え前に必要。
element: 熱=1、水=2、風=3、光=4、土=5。今回採用した固定対応。
無属性や6番は資料で未定義のため作成しない。
花データだからね。エクセルみても無属性がないのだよ
どちらかというと、スキルデータ側含むでいまのところは無属性いない。
status_bonus: hp/mp/atk/def/cd。ハスのみ資料にある exp=5（取得経験値+5%）も保持。
hanakotoba: 花言葉の配列
path: ゲーム画像のファイル名。path.json.game と連結。
real_path: 写真のファイル名が異なる場合のみ指定。写真は path.json.real + (real_path ?? path)。
画像の既存ファイル名を変えずに参照するため、004/007/009/010に real_path を設定。
description: 花の説明
origin: 起源 / habitat: 咲いている場所 / features: 特徴
これら図鑑項目はDBを介さずJSONで管理する。
date: 資料J列の日付（前回の花博で出た日付。用途未定）。資料の空欄は空文字。
