## 1. 目的と対象

プレイヤーが登録からストーリー・戦闘・契約・育成まで一連の操作を完了し、進行・所持品・コインが整合して保存されることを確認する。画面操作、TypeScriptの計算・状態遷移、PHP API、DB・ブラウザ保存の連携を対象とする。

実装を参照して作成した仕様書であり、ケースの実行結果を示すものではない。全ケースを「未実施」で初期化している。期待結果には正常動作として確認すべき要件も含むため、現在のコードで達成されていなければ不具合として記録する。

管理機能、Google認証、未整備エリア、オフライン復帰は確認事項を併記した。仕様未確定の項目は「仕様確認待ち」とし、現挙動だけを根拠に合格としない。

### テストデータセット

| 記号 | 状態 |
| --- | --- |
| A | テスト用の新規ユーザー。未クリア状態と通常進行状態を使い分ける |
| B | Aと異なる名前・コイン・編成・所持花・進行を持つユーザー |
| F | 育成対応花、未所持花、スキル未対応花、各レア度、各実装済みスキルtypeの代表花 |
| I | 治療薬12、回復薬13、攻撃宝石14、防御宝石15、各栄養剤・種。それぞれ0・1・複数所持 |
| C | コイン0、価格合計より1不足、価格合計と同額、十分な残高、上限直前 |
| H | 単体HP用に最大HP100と1000を固定。プレイ中の通常能力値とは区別する |
| N | 正常通信、低速、処理前遮断、サーバー成立後の応答遮断、DB途中失敗 |
| L | 正常キャッシュ、未保存、不正JSON、旧編成v1/v2、保存禁止 |

各ケースの前に初期値を復元する。期待値を比較するときは、コイン・アイテム・花所持・レベル・累計EXP・クリアIDの前後値を残す。テスト用の状態注入は単体環境または専用データ準備で行い、本番アカウントへ適用しない。

## 3. 判定と記録方法

P0は進行不能・誤消費・誤保存・認証・重複処理に直結する優先項目、P1は表示・境界値・復帰・互換性などの確認項目とする。

実施結果は「未実施」「合格」「不合格」「保留」「対象外」を使用する。保留・対象外には理由を記入する。実測・証跡欄には画面画像、Network記録、API応答、前後のDB値、実施者、実施日時、不具合IDを関連付ける。個人情報・パスワード・認証トークンは証跡へ残さない。

時間の厳密な境界は制御時計による単体テストで判定する。手動確認では「3秒より前に減らない」「3秒後に追従する」を映像で確認する。フレームによる最大1更新分の遅れは許容し、バックグラウンドタブの抑制時間を混ぜない。

HP白バーは現在の実装値である毎秒最大HPの25%を基準とする。追加被弾が最後の被弾時刻を更新し、回復によるHP増加では待機を延長しない。戦闘の一時停止中は経過時間を進めない。

| Q-08 | 操作案内と主人公設定の一致 | 戦闘導入の案内は初戦のHUD表示で実装されている。主人公は管理設定で切り替え可能だが、ストーリーの立ち絵は固定画像の参照がある。公開仕様と一致するか確認する |
| Q-09 | 応答欠落時の操作再送 | 購入・契約等はDB処理成立後に応答を失う場合がある。SAVE-009で二重成立と再取得を検証し、再送単位・救済方針を確定する |
| Q-10 | ログ・確認中のAUTO挙動 | StorySceneのポップアップとAUTOタイマーの連携をSTORY-008で確認する。会話が進む場合は記録し、閲覧・確認中に停止する仕様として修正要否を判断する |

## 6. 推奨する実施順序

1. BOOT、AUTHのP0を実施し、ログインと基本導線を確認する。
2. QUALITY-010の全体通しを行い、進行を止める不具合を抽出する。
3. BATTLE、HP、PLAYER、SKILLのP0、続いて契約・購入・育成・保存のP0を実施する。
4. 通信失敗・同時要求・データ不正・旧形式移行を実施する。
5. 残るP1と各環境での表示・音声・繰り返し操作を実施する。
6. 修正箇所に対応するケースと全体通しを再実施し、関連データの整合性を確認する。

## 7. 完了条件案

P0を全件実施し、不合格を解消する。対象機能のP1を実施し、残る不具合と影響範囲を記録する。Q項目で未確定の要件を確定し、公開範囲に関わる保留を解消する。登録から初戦・契約・購入・育成・再ログインの通し操作が対象環境で完了し、前後データの整合性を確認できることを完了条件とする。

この完了条件は本仕様書の提案であり、既存のリリース規則として追加したものではない。

## 9. メンテナンス方法

機能・マスター・API・保存形式を変更した場合は、対応するケースの前提値と期待結果を更新する。スキルの追加ではSKILL-008に実装typeと代表花を追記し、ステージ追加ではHOME・BATTLE・SAVEのID対応を更新する。実施時のコミットとマスター値を必ず残し、後日の変更と実施結果を混同しない。
